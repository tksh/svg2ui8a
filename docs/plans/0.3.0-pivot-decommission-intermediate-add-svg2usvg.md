# 0.3.0 pivot — decommission Straightlines / CBOR / `intermediate`, keep `svg2rgba`, add `svg2usvg` (`Uint8Array` of usvg bytes)

> Status: APPROVED & IMPLEMENTED — human approved all five §11 answers;
> implementation complete, `task.md` §16 checked, verification green.
>
> Builds on top of `0.2.0` (Straightlines freeze + `svg2rgba`, shipped). This
> plan replaces that baseline; it does not re-derive it. The companion checklist
> is `task.md` §16.

## 1. Problem statement and authorization

The two-stage Straightlines pipeline (`svg2stln` → canonical CBOR → `stln2rgba`)
was built to make the cache-hit path cheap: hash the CBOR bytes, skip the SVG
parse, rehydrate a `usvg::Tree` cheaply on render. That premise fails against
the real `usvg 0.47` implementation. `usvg::Tree`'s node structs use
`pub(crate)` fields and lack public constructors; the only public way to obtain
a `Tree` is `Tree::from_str` / `from_data` parsing an SVG/XML string. The
`intermediate` → `Tree` step therefore **must serialize its DTO back to a
minimal SVG string and re-parse it** before `resvg::render` can run — the
re-parse the intermediate was meant to avoid is unavoidable, and any per-shape
encoding change (e.g. numeric `path_data`) merely moves formatting work onto
that hot path rather than removing it. Recorded as implementer judgment in
`docs/plans/baseline-implementation.md` and confirmed again during the numeric
`path_data` review, this bottleneck is architectural, not a codec choice.

Because the bottleneck is structural, the human has decided to pivot:

- Discard all code supporting the `tksh/Straightlines` proprietary format:
  `svg2stln` and `stln2rgba` are abolished; no proprietary intermediate is
  maintained.
- Discard all CBOR processing and the `cbor-core` crate.
- Keep `svg2rgba` with its current functionality (SVG → RGBA `Uint8Array`).
- Add `svg2usvg` (new, distinct from the legacy same-named function): SVG string
  in → usvg-out `Uint8Array` — the UTF-8 bytes of the normalized usvg XML
  string, not a JS `string` return.
- Both exports are `Uint8Array`-in/out (`svg2ui8a` naming), each its own
  independently-loadable Wasm artifact with its own subpath import.
- Fonts (text rendering) and BBox features are postponed — currently out of
  scope, but explicitly deferred rather than permanently forbidden. If needed,
  the package will become a more faithful `linebender/resvg` wrapper, without
  chasing every upstream release and without adding unique features not present
  in `resvg`.
- Version `0.3.0`; obsolete `.md` plans moved to `docs/archive/` as a record
  that the strategy did not work out; `CHANGELOG.md` honestly describes the
  failure.

This plan is authorized by `docs/project-constitution.md` §1 (`Uint8Array`
mission) and §2 (product definitions — to be rewritten for two products), §4
(API surface shape), and `docs/engineering-playbook.md` §4 (plan-before-act). It
requires the human to grant the `AGENTS.md` §8 exception for editing the four
governing documents, as part of approving the plan.

## 2. Product decisions (post-pivot)

| Subpath                       | Function                  | Input        | Output                                              | Wasm                      |
| ----------------------------- | ------------------------- | ------------ | --------------------------------------------------- | ------------------------- |
| `jsr:@tksh/svg2ui8a/svg2rgba` | `svg2rgba(svg, options?)` | SVG `string` | `Promise<RgbaResult>` (`pixels: Uint8Array`)        | `assets/svg2rgba_bg.wasm` |
| `jsr:@tksh/svg2ui8a/svg2usvg` | `svg2usvg(svg)`           | SVG `string` | `Promise<Uint8Array>` (UTF-8 bytes of the usvg XML) | `assets/svg2usvg_bg.wasm` |
| `jsr:@tksh/svg2ui8a`          | re-exports both           | —            | —                                                   | —                         |

- `svg2usvg(svg: string): Promise<Uint8Array>` — parses with feature-disabled
  `usvg` (reject `<text>` / `<image>`), then writes the normalized tree back to
  XML via `usvg::Tree::to_string` / `XmlOptions`-equivalent API and returns its
  UTF-8 bytes (`Vec<u8>` → `Uint8Array` at the Wasm boundary). The return is
  bytes, not a JS `string`, so **every public payload remains `Uint8Array`**
  (`constitution` §1) and the package name `svg2ui8a` reads literally for both
  exports. No options parameter (`svg2stln` had none; same shape here).
- `svg2rgba` — unchanged contract:
  `svg2rgba(svg, options?): Promise<RgbaResult>` with
  `width?`/`height?`/`alphaMode?`, straight-alpha default, sizing rule
  `constitution` §4.3. No envelope, no `intermediate`, no cacheable-bytes
  contract beyond "same input → same pixels".
- Fonts/BBox: constitution §3.1/§3.2 change from "hard forbidden" to "postponed
  — may be added later as a faithful `resvg` wrapper, without chasing latest
  upstream releases and without adding package-unique features".
- Serialization: constitution §3.7 "CBOR is the serialization format" is
  removed; the package has no custom serialization. `svg2usvg`'s bytes are
  standard SVG XML (UTF-8), produced by `usvg` itself.

## 3. Architecture changes

- **Workspace:** `Cargo.toml` members shrink from four to two:
  `crates/svg2usvg` + `crates/svg2rgba`. `intermediate`, `svg2stln`, `stln2rgba`
  removed. `[workspace.dependencies]` drops `cbor-core = "0.10.1"`; retains
  `usvg 0.47.0` / `resvg 0.47.0` `default-features = false` and `wasm-bindgen`.
- **`crates/svg2usvg` (new):** `core.rs` with
  `pub fn svg(svg: &str) ->
  Result<Vec<u8>, String>` — rejects
  `<text>`/`<image>` (lowercase scan, matching `svg2rgba`/`svg2stln`), parses
  with `usvg::Options::default()` (feature-disabled), handles text/image absence
  via tree walk if desired, then serializes via `Tree::to_string` (or
  `to_string_with_opt` / `XmlOptions`) to `Vec<u8>`. `lib.rs` with
  `#[wasm_bindgen] pub fn svg2usvg(svg: &str) ->
  Result<Box<[u8]>, JsValue>`
  (sync export; TS wrapper makes it `Promise`). Depends only on `usvg` +
  `wasm-bindgen`.
- **`crates/svg2rgba` (kept):** unchanged `core.rs`/`lib.rs` byte-for-byte
  except any incidental import clean-up; docs updated to note it is now one of
  two peers rather than one of three. Feature-verification remains
  `text`/`system-fonts`/`raster-images` excluded.
- **Deleted:** `crates/intermediate`, `crates/svg2stln`, `crates/stln2rgba` (all
  `src/`, `examples/`, `tests/`, `Cargo.toml`), the Straightlines `.cbor`
  fixture, and any CBOR `dump_core` examples.
- **Build:** `scripts/build.ts` compiles two crates only, copies to
  `assets/svg2usvg_bg.wasm` / `assets/svg2rgba_bg.wasm`, regenerates
  `src/svg2usvg.ts` + `src/svg2rgba.ts` (each embeds its Wasm as base64, calls
  `__wbg_init` with bytes — no runtime fetch, `constitution` §3.8), regenerates
  `src/mod.ts`, verifies two independent Wasm modules and that neither contains
  the other's export, then runs the CDN-free check.
- **TS surface:** `src/svg2usvg.ts` mirrors the current `stln.ts` shape but for
  the new name; `src/svg2rgba.ts` unchanged shape; `src/mod.ts` re-exports
  `{ svg2usvg, svg2rgba }`.
- **JSR:** `deno.json` (`jsr.json`) exports become `"."`, `"./svg2rgba"`,
  `"./svg2usvg"`; `version` → `"0.3.0"`; `publish.exclude` unchanged;
  `tasks.test:rust` runs two crates; `fixtures:regen` removed.

## 5. Tests — additions, removals, updates

**Removed:** every Straightlines/CBOR/intermediate test — `intermediate` round-
trip/rejection, envelope identifier/version, group-depth limit, `svg2stln`
subset-freeze rejections, `stln2rgba` CBOR decode + rehydrate, `.cbor` fixture
read-back, golden pixel-equality via intermediate, the `SVGS` diagonal fixtures
that exercised `stln` in `scripts/test-wasm*.ts`.

**Kept/added:**

- `crates/svg2usvg` native (`cargo test`): simple SVG → non-empty `Vec<u8>`;
  same SVG → identical bytes (determinism); malformed SVG → error; `<text>` →
  error; `<image>` → error; output bytes are valid UTF-8 and re-parse via
  `usvg::Tree::from_str`; feature verification excludes `text`/`system-fonts`/
  `raster-images`.
- `crates/svg2rgba` native: unchanged (natural size, width-only/height-only,
  non-uniform both, zero-size, straight `255,0,0,128` vs premultiplied
  `128,0,0,128`, determinism, malformed/`<text>`/`<image>`).
- Wasm layer: `svg2usvg` returns `Promise<Uint8Array>` and matches its native
  core byte-for-byte; `svg2rgba` as before.
- Deno layer (`deno test -A`): `svg2usvg` returns `Uint8Array`, `TextDecoder`
  round-trip is valid XML; `svg2rgba` returns `RgbaResult` with
  `pixels.length === width*height*4` and correct `alphaMode`; `svg2usvg` →
  `svg2rgba` is not a pipeline (the usvg bytes are XML; `svg2rgba` already
  accepts arbitrary SVG, so a smoke call proves bytes are well-formed); `init`
  idempotency per module; determinism; malformed rejects; plain-object
  `RgbaResult` checks (`Object.prototype`, no `free()`, `structuredClone` /
  `JSON` round-trip) remain for `svg2rgba`; no `__wasm_` exports.
- Browser harness: Astral/CDP headless Chrome loads `src/svg2usvg.ts` +
  `src/svg2rgba.ts` and asserts the same two guarantees.

## 7. Versioning and `CHANGELOG.md` entry

Target: **`0.3.0`** (human-directed). Pre-1.0 minor that breaks the API: the two
Straightlines subpaths (`./svg2stln`, `./stln2rgba`) are removed and
`./svg2usvg` is added; any cached `.cbor` bytes from `0.2.0` are no longer
decodable (intentional). The entry must be honest about the failure:

> `0.3.0` — Remove the Straightlines / CBOR intermediate (`svg2stln`,
> `stln2rgba`, `intermediate` crate, `cbor-core`, Straightlines fixtures and
> their tests) because the custom representation failed to make cache-hit
> renders cheaper: `usvg::Tree` can only be reconstituted by re-parsing SVG XML,
> so the intermediate's re-serialization round-trip cannot bypass the re-parse
> it was designed to avoid. Keep `svg2rgba` unchanged; add `svg2usvg`
> (`crates/svg2usvg`, `src/svg2usvg.ts`, `assets/svg2usvg_bg.wasm`) that returns
> the UTF-8 bytes of the normalized usvg XML as `Uint8Array` — every public
> payload remains `Uint8Array` (`svg2ui8a`). Both exports are independent Wasm
> artifacts with independent subpath imports. Move superseded Straightlines /
> CBOR plan documents to `docs/archive/` as a historical record. Postpone
> fonts/BBox (may become a faithful `linebender/resvg` wrapper later; no chase
> of latest upstream, no package-unique features).

`deno.json` version → `0.3.0`. No `FORMAT_VERSION` remains (format is standard
SVG XML, not versioned).
