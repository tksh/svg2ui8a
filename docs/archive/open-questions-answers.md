## R4. Alpha handling

**Decision**:

- Default `alphaMode: "straight"` (auto-unpremultiply).
- Optional `alphaMode: "premultiplied"` to skip the unmultiply
  step (the caller wants the `tiny-skia` pixmap bytes as-is).
- The option is a string literal, not a boolean, so future modes
  can be added without an API break.

### Edits

- `docs/project-constitution.md` §4.2 (`Usvg2RgbaOptions`):

  ```ts
  export type AlphaMode = "straight" | "premultiplied";

  export interface Usvg2RgbaOptions {
    width?: number;
    height?: number;
    alphaMode?: AlphaMode;   // default: "straight"
  }
  ```

  And update `RgbaResult` to carry the chosen alpha mode:

  ```ts
  export interface RgbaResult {
    pixels: Uint8Array;
    width: number;
    height: number;
    alphaMode: AlphaMode;   // matches the option that produced it
  }
  ```

- `docs/project-constitution.md` §5.2: add a sentence: "Pixels are
  `straight` (non-premultiplied) by default. When the caller passes
  `alphaMode: "premultiplied"`, the bytes are the unmodified
  `tiny-skia` pixmap, with channels premultiplied by alpha."
- `docs/project-constitution.md` §7: no change (the contract is
  about `postcard` determinism, not pixels).
- `docs/system-architecture.md` §4.2: the `Rust` sample should
  decode `alphaMode`, branch on it, and return it as part of
  `RgbaResult`. The default branch does the unmultiply on
  `pixmap.pixels()`.
- `docs/engineering-playbook.md` §3.2 (native tests) and §3.4
  (Deno tests): add a test for both alpha modes. The "straight"
  test should verify a known pixel value, e.g. a 50%-opaque red
  becomes `(255, 0, 0, 128)` not `(128, 0, 0, 128)`. The
  "premultiplied" test should verify the same input produces
  `(128, 0, 0, 128)`.

### Implementation note (for the eventual Rust code)

`tiny-skia`'s pixmap is premultiplied. To unmultiply:

```rust
fn unpremultiply(pixmap: &tiny_skia::Pixmap) -> Vec<u8> {
    let mut out = pixmap.data().to_vec();
    for chunk in out.chunks_exact_mut(4) {
        let a = chunk[3] as u32;
        if a == 0 {
            chunk[0] = 0; chunk[1] = 0; chunk[2] = 0;
        } else {
            chunk[0] = ((chunk[0] as u32 * 255) / a).min(255) as u8;
            chunk[1] = ((chunk[1] as u32 * 255) / a).min(255) as u8;
            chunk[2] = ((chunk[2] as u32 * 255) / a).min(255) as u8;
        }
    }
    out
}
```

`alphaMode: "premultiplied"` skips this and returns
`pixmap.data().to_vec()`.

## R5. Independent scaling for `width` / `height`

**Decision**: independent scaling. The output is exactly
`width × height`. Aspect ratio is not preserved unless the caller
happens to pass the natural size.

### Edits

- `docs/project-constitution.md` §4.2: add a sentence to
  `Usvg2RgbaOptions`: "If both `width` and `height` are omitted,
  the natural SVG size is used. If only one is provided, the
  other is taken from the natural SVG size — the output is
  exactly `width × height`, with non-uniform scaling if the aspect
  ratio of `(width, height)` does not match the natural aspect
  ratio. This is a deliberate design choice, not a bug."
- `docs/project-constitution.md` §8.2 (failure modes): clarify
  that the natural size comes from `tree.size()` and is in user
  units; the cast to `u32` is rounding toward zero (i.e. `f32` /
  `f64` → `u32` via `as u32` in Rust). This is acceptable because
  the natural size of an SVG is in practice always a small
  integer; pathological floats are the caller's problem.
- `docs/system-architecture.md` §4.2: the Rust sample's
  `Transform::from_scale(width / natural_w, height / natural_h)`
  is correct under R5. No code change; no doc change.
- `docs/engineering-playbook.md` §3.2 / §3.4: add a test that
  passes only `width`, and asserts the output is `width × natural_h`.

### OQ-3.4 — Does `usvg::Tree` round-trip through `postcard`?

**Resolution**: this is a real technical assumption. It is
**not verified** in the four documents, and the agent must
verify it before the first implementation.

Verification steps:

1. Write a small Rust test that does:
   ```rust
   let svg = r#"<svg viewBox="0 0 10 10"><rect width="10" height="10" fill="red"/></svg>"#;
   let tree = usvg::Tree::from_str(svg, &usvg::Options::default()).unwrap();
   let bytes1 = postcard::to_stdvec(&tree).unwrap();
   let tree2: usvg::Tree = postcard::from_bytes(&bytes1).unwrap();
   let bytes2 = postcard::to_stdvec(&tree2).unwrap();
   assert_eq!(bytes1, bytes2, "postcard round-trip must be stable");
   ```
2. Run it. If it passes, the architecture is sound.
3. If `postcard::from_bytes` returns an error or a different
   `Tree`, the agent must **stop and escalate per `AGENTS.md`
   §10**. The constitution (§3.7) forbids switching formats,
   so an unsolvable postcard issue would block the entire
   project and require a constitution-level decision.

### Edits

- `docs/engineering-playbook.md` §3.1: add the round-trip
  test from above as a **required** test case for
  `svg2usvg`.
- `docs/engineering-playbook.md` §3.2: add a reciprocal test
  for `usvg2rgba`: given the bytes from a `svg2usvg` call,

### OQ-5.3 — How native `cargo test` calls `#[wasm_bindgen]` exports

**Resolution**: the Rust code is structured so that
**non-`#[wasm_bindgen]` core functions** are tested
natively, and the thin `#[wasm_bindgen]` wrappers are
tested in the Wasm layer.

Concretely:

```rust
// crates/usvg2rgba/src/lib.rs

// Pure Rust, no bindgen. Tested natively.
pub fn usvg2rgba_core(usvg_bytes: &[u8], opts: &RgbaOptions) 
    -> Result<RgbaResultCore, RenderError> {
    let tree: usvg::Tree = postcard::from_bytes(usvg_bytes)?;
    // ... actual logic ...
    Ok(RgbaResultCore { pixels, width, height, alpha_mode })
}

// Thin wrapper. Tested in Wasm only.
#[wasm_bindgen]
pub fn usvg2rgba(usvg_bytes: &[u8], options: Option<JsValue>) 
    -> Result<JsValue, JsError> {
    let opts: RgbaOptions = match options {
        Some(v) => serde_wasm_bindgen::from_value(v)?,
        None => RgbaOptions::default(),
    };
    let core = usvg2rgba_core(usvg_bytes, &opts)?;
    Ok(/* serialize core to JsValue */)
}
```

### Edits

- `docs/system-architecture.md` §4.2: rewrite the sample
  to use the `core` / wrapper split. The `core` function
  is what `cargo test` exercises; the `#[wasm_bindgen]`
  wrapper is what the Wasm tests exercise.
- `docs/engineering-playbook.md` §3.1, §3.2: change
  "exercise the `svg2usvg` function directly" to
  "exercise `svg2usvg_core` (the non-bindgen function)".

**Resolution**: the agent formats only lines it has
touched. Pre-existing drift in the tree is **not** the
agent's problem to fix in the same change. If the agent
runs `deno fmt` on the whole tree and the diff includes
untouched lines, those lines are reverted before
committing.

  `deno fmt` on the whole tree and reverts changes to
  files the agent did not touch".

### OQ-6.4 — Root re-export and tree-shaking

**Resolution**: the root `mod.ts` re-export is **not**
required to enable tree-shaking. The subpath imports
(`jsr:@tksh/svg2ui8a/usvg`,
`jsr:@tksh/svg2ui8a/rgba`) are the supported way to
import a single Wasm artifact. The root re-export is a
convenience for consumers who want both.

Bundler support: the package is tested against
`deno bundle` and against one modern browser bundler
(specify which one when the build pipeline is
implemented; the default candidate is `esbuild`, but
this is not a current decision).

### Edits

- `docs/system-architecture.md` §2.1: add a sentence:
  "Subpath imports are the supported way to load a
  single Wasm artifact. The root import is a convenience
  for consumers who want both; it does not enable any
  tree-shaking that the subpath imports would not
  already enable."
- `docs/system-architecture.md` §2: drop the sentence
  "The bundler is expected to tree-shake whichever
  subpath is not used." It is not the bundler's
  responsibility; the subpath import is what selects
  the artifact.

### OQ-7.3 — Transparent background / pixmap clear

**Resolution**: the pixmap is allocated with
`tiny_skia::Pixmap::new(w, h)`, which initializes all
bytes to zero (fully transparent black). The contract
is: the output RGBA buffer has zero alpha for any pixel
that the SVG did not paint.

### Edits

- `docs/project-constitution.md` §5.2: add a sentence:
  "Any pixel not painted by the SVG has zero alpha (and
  zero RGB). The output buffer is fully zero-initialized
  before the SVG is drawn."
